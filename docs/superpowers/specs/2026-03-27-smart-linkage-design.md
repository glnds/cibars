# Smart Linkage — Corrected Design Spec

Based on a full read of the actual source. All struct/function names are from the real code.

---

## What linkage currently does

`discover_links()` in `main.rs` runs once at startup. It fetches every
`.github/workflows/*.yml` file via `fetch_workflow_files()`, extracts `aws s3 cp/sync`
targets, then cross-references those S3 keys against each CodePipeline's source S3
config. Matches are stored in a local `LinkMap` in `run_poll_orchestrator`. The `LinkMap`
also does runtime correlation: if a GH workflow completes and a CP pipeline starts within
30 seconds, `try_correlate()` adds a `RuntimeCorrelated` link.

`link_map` is **not in `App`** — it lives as a local variable in
`run_poll_orchestrator` and is never visible to the UI. Only its side effects are
visible: `pending_link` on `PipelineGroup`, and the suppression of Running workflows
whose linked pipeline has started.

---

## Design decisions

**Tree rendering**: The current UI has two separate bordered blocks — `GitHub Actions`
and `CodePipelines`. The tree view merges linked pairs: a linked `PipelineGroup` is
rendered indented directly under its parent `WorkflowGroup` inside the Actions block.
The CodePipelines block then only shows pipelines with no active link. This avoids a
full layout redesign while making the GH→CP relationship visually obvious.

**Cache file location**: `cwd/.cibars-links.toml`, same directory as `config.toml`.
The `cwd` is already used in `main()` for `Config::load(&cwd)`.

**`'l'` key mechanism**: `link_map` and `discover_links` live in the async poll
orchestrator, not the UI. Consistent with how the boost key works, a new
`Arc<Notify>` (`link_notify`) is passed to both `run_ui` (to trigger it) and
`run_poll_orchestrator` (to act on it).

**`recent_completions` in `LinkMap`**: not persisted — it's runtime-only transient
state. The cache stores only the `Vec<PipelineLink>`.

## 1. `.cibars-links.toml` schema

```toml
# Auto-generated by cibars. Re-run discovery with 'l'.
schema_version = 1
discovered_at = "2026-03-27T14:22:08Z"

[[links]]
pipeline_name = "prod-frontend-pipeline"
workflow_name  = "deploy-frontend"
s3_bucket      = "my-bucket"
s3_key         = "frontend/dist.zip"
source         = "YamlDiscovered"

[[links]]
pipeline_name = "ci-test-pipeline"
workflow_name  = "build-and-test"
s3_bucket      = ""
s3_key         = ""
source         = "RuntimeCorrelated"
```

`source` is serialized from `LinkSource` as a string tag. `s3_bucket`/`s3_key` are
empty strings for `RuntimeCorrelated` links (no S3 evidence, just timing).

## 2. `src/linkage.rs` changes

### New structs for cache serialization

```rust
use serde::{Deserialize, Serialize};

#[derive(Serialize, Deserialize, Debug, Clone)]
pub struct CachedLink {
    pub pipeline_name: String,
    pub workflow_name: String,
    pub s3_bucket: String,
    pub s3_key: String,
    pub source: CachedLinkSource,
}

#[derive(Serialize, Deserialize, Debug, Clone)]
pub enum CachedLinkSource {
    YamlDiscovered,
    RuntimeCorrelated,
}

#[derive(Serialize, Deserialize, Debug)]
pub struct LinkCache {
    pub schema_version: u32,
    pub discovered_at: String,
    pub links: Vec<CachedLink>,
}
```

`CachedLink` mirrors `PipelineLink` but derives `Serialize/Deserialize`.
`PipelineLink` itself doesn't need serde — only the cache struct does.

### New methods on `LinkMap`

```rust
impl LinkMap {
    /// Populate from a loaded cache (replaces any existing links).
    pub fn load_from_cache(&mut self, cache: LinkCache) {
        self.links.clear();
        for cl in cache.links {
            self.links.push(PipelineLink {
                pipeline_name: cl.pipeline_name,
                workflow_name: cl.workflow_name,
                s3_bucket: cl.s3_bucket,
                s3_key: cl.s3_key,
                source: match cl.source {
                    CachedLinkSource::YamlDiscovered => LinkSource::YamlDiscovered,
                    CachedLinkSource::RuntimeCorrelated => LinkSource::RuntimeCorrelated,
                },
            });
        }
    }

    /// Serialize current links to a cache struct (ready to write to disk).
    pub fn to_cache(&self, discovered_at: &str) -> LinkCache {
        LinkCache {
            schema_version: 1,
            discovered_at: discovered_at.to_string(),
            links: self.links.iter().map(|l| CachedLink {
                pipeline_name: l.pipeline_name.clone(),
                workflow_name: l.workflow_name.clone(),
                s3_bucket: l.s3_bucket.clone(),
                s3_key: l.s3_key.clone(),
                source: match l.source {
                    LinkSource::YamlDiscovered => CachedLinkSource::YamlDiscovered,
                    LinkSource::RuntimeCorrelated => CachedLinkSource::RuntimeCorrelated,
                },
            }).collect(),
        }
    }

    /// Remove all links (before re-discovery).
    pub fn clear(&mut self) {
        self.links.clear();
        self.recent_completions.clear();
    }

    /// True if pipeline_name appears in the known links.
    pub fn has_pipeline(&self, name: &str) -> bool {
        self.links.iter().any(|l| l.pipeline_name == name)
    }

    /// True if workflow_name appears in the known links.
    pub fn has_workflow(&self, name: &str) -> bool {
        self.links.iter().any(|l| l.workflow_name == name)
    }
}
```

### New standalone functions

```rust
/// Load link cache from disk. Returns None if file doesn't exist.
pub fn load_link_cache(
    path: &std::path::Path,
) -> anyhow::Result<Option<LinkCache>> {
    match std::fs::read_to_string(path) {
        Ok(contents) => {
            let cache: LinkCache = toml::from_str(&contents)
                .context("failed to parse .cibars-links.toml")?;
            if cache.schema_version != 1 {
                return Ok(None);
            }
            Ok(Some(cache))
        }
        Err(e) if e.kind() == std::io::ErrorKind::NotFound => Ok(None),
        Err(e) => Err(e.into()),
    }
}

/// Write link cache atomically (write to .tmp, then rename).
pub fn save_link_cache(
    path: &std::path::Path,
    cache: &LinkCache,
) -> anyhow::Result<()> {
    let body = toml::to_string_pretty(cache)
        .context("failed to serialize link cache")?;
    let content = format!(
        "# Auto-generated by cibars. Re-run discovery with 'l'.\n\n{body}"
    );
    let tmp = path.with_extension("toml.tmp");
    std::fs::write(&tmp, content.as_bytes())
        .context("failed to write .cibars-links.toml.tmp")?;
    std::fs::rename(&tmp, path)
        .context("failed to rename link cache into place")?;
    Ok(())
}
```

`toml` and `anyhow` are already in `Cargo.toml`. `serde` with `derive` feature is
already present.

## 3. `src/app.rs` changes

Two new fields on `App`:

```rust
pub struct App {
    // ... existing fields unchanged ...

    /// True when a previously loaded link map has stale references.
    pub linkage_broken: bool,

    /// True while discover_links() is running (blocks second trigger).
    pub linkage_discovering: bool,
}
```

Initialize both to `false` in `App::new()`.

### New method: `check_linkage_health`

```rust
impl App {
    /// Compare link map against live data.
    /// Should only be called after loading_pipelines AND loading_actions are false.
    pub fn check_linkage_health(
        &mut self,
        link_map: &crate::linkage::LinkMap,
    ) {
        if self.loading_pipelines || self.loading_actions {
            return;
        }
        if link_map.links().is_empty() {
            self.linkage_broken = false;
            return;
        }

        let ghost_pipeline = link_map.links().iter().any(|l| {
            !self.pipeline_groups.iter().any(|pg| pg.name == l.pipeline_name)
        });
        let ghost_workflow = link_map.links().iter().any(|l| {
            !self.workflow_groups.iter().any(|wg| wg.name == l.workflow_name)
        });

        self.linkage_broken = ghost_pipeline || ghost_workflow;
    }
}
```

`link_map` is passed in as a parameter so it doesn't need to live in `App` — it
stays local to the orchestrator.

## 4. `src/main.rs` changes

### New `link_notify` signal

```rust
// In main(), alongside boost_notify:
let link_notify = Arc::new(tokio::sync::Notify::new());
```

Pass it to both `run_ui(...)` and `run_poll_orchestrator(...)`.

### Startup: cache-first loading

In `run_poll_orchestrator`, replace the current `discover_links` call:

```rust
let cache_path = cwd.join(".cibars-links.toml");

match linkage::load_link_cache(&cache_path) {
    Ok(Some(cache)) => {
        link_map.load_from_cache(cache);
        tracing::info!(
            links = link_map.links().len(),
            "loaded link cache from disk"
        );
    }
    Ok(None) => {
        link_map = discover_links(&client, &gh_client).await;
        // persist
    }
    Err(e) => {
        tracing::warn!(error = %e, "corrupt link cache, re-running discovery");
        let _ = std::fs::remove_file(&cache_path);
        link_map = discover_links(&client, &gh_client).await;
        // persist
    }
}
```

### New helper: `run_discovery`

Extract `discover_links` into a helper that also persists and updates app state:

```rust
async fn run_discovery(
    aws: &dyn PipelineClient,
    gh: &dyn ActionsClient,
    app: &Arc<Mutex<App>>,
    cache_path: &std::path::Path,
) -> LinkMap {
    app.lock().unwrap().linkage_discovering = true;

    let link_map = discover_links(aws, gh).await;

    // Persist
    if !link_map.links().is_empty() {
        let cache = link_map.to_cache(&chrono::Utc::now().to_rfc3339());
        if let Err(e) = linkage::save_link_cache(cache_path, &cache) {
            tracing::warn!(error = %e, "failed to save link cache");
        }
    }

    app.lock().unwrap().linkage_discovering = false;
    link_map
}
```

### `'l'` key handler in orchestrator loop

In the `tokio::select!` inside the poll loop, add the `link_notify` signal:

```rust
tokio::select! {
    biased;
    _ = boost_notify.notified() => { /* existing boost handling */ }
    _ = link_notify.notified() => {
        // Clear and re-discover
        link_map.clear();
        if let Some(aws) = aws_client.as_ref() {
            link_map = run_discovery(aws, &gh_client, &app, &cache_path).await;
        }
        app.lock().unwrap().linkage_broken = false;
    }
    _ = sigusr1.recv() => { /* existing SIGUSR1 handling */ }
    _ = async { /* existing poll */ } => { /* ... */ }
}
```

### Health check after each poll cycle

After `apply_links(...)` in the poll loop:

```rust
{
    let mut a = app.lock().unwrap();
    a.check_linkage_health(&link_map);
}
```

## 5. `src/ui/mod.rs` changes — tree rendering

### Core concept

Linked `PipelineGroup`s are pulled out of the CodePipelines block and rendered
indented under their parent `WorkflowGroup` in the Actions block. The CodePipelines
block only shows pipelines with no active link.

To make this work, the UI needs to know which pipeline is linked to which workflow.
Add a `linked_pipeline: Option<String>` field to `WorkflowGroup`:

```rust
// in src/model.rs, WorkflowGroup struct:
pub linked_pipeline: Option<String>,
```

Set in the orchestrator after discovery/cache-load and after each poll that adds new
workflow groups.

### `sorted_pipeline_groups` — filter out linked pipelines

```rust
fn sorted_pipeline_groups<'a>(
    groups: &'a [PipelineGroup],
    workflow_groups: &[WorkflowGroup],
) -> Vec<&'a PipelineGroup> {
    let linked: std::collections::HashSet<&str> = workflow_groups
        .iter()
        .filter_map(|wg| wg.linked_pipeline.as_deref())
        .collect();

    let mut sorted: Vec<&PipelineGroup> = groups
        .iter()
        .filter(|g| !linked.contains(g.name.as_str()))
        .collect();
    sorted.sort_by(|a, b| {
        let a_running = a.stages.iter().any(|s| s.status == BuildStatus::Running);
        let b_running = b.stages.iter().any(|s| s.status == BuildStatus::Running);
        b_running.cmp(&a_running).then(a.name.cmp(&b.name))
    });
    sorted
}
```

### Row counting — include linked pipeline rows in action_rows

The CI job count must include rows for linked pipeline headers + stages.

### Render loop — inject pipeline after each linked workflow

Within the CI workflow render loop, after rendering each workflow group's jobs,
if the group has a `linked_pipeline`, render it indented:

```
● build-and-test     ████████████████  2m ago
● test               ████████████████  ok
└─ ● prod-pipeline  Running
    Source   ████████████████  ok
    Build    ◉◉◉◉◉◉◉◉◉◉◉◉◉◉◉◉
    Deploy   ░░░░░░░░░░░░░░░░
```

### Keeping `linked_pipeline` up to date

```rust
fn sync_linked_pipelines(app: &Arc<Mutex<App>>, link_map: &LinkMap) {
    let mut a = app.lock().unwrap();
    for wg in &mut a.workflow_groups {
        wg.linked_pipeline = link_map.links().iter()
            .find(|l| l.workflow_name == wg.name)
            .map(|l| l.pipeline_name.clone());
    }
}
```

Call after discovery, cache load, and after each poll that adds new workflow groups.
